# Instructions Management

**Status:** in-progress  
**Last updated:** 2026-05-14

## What this is

Copilot instructions are currently split across multiple files with inconsistent
tracking. Universal instructions (behaviour rules, skill invocation) are mixed into an
untracked file alongside system-specific paths. The `COPILOT_CUSTOM_INSTRUCTIONS_DIRS`
env var that loads `~/.agents/AGENTS.md` is set but not tracked in any dotfile, making
it fragile across machines. The goal is a system that tracks everything trackable,
keeps system-specific paths out of git, and loads reliably on every machine.

## Goals

- All non-machine-specific instruction content tracked in git (dotfiles or agents repo)
- System-specific paths injected at apply time, not hardcoded in tracked files
- Reliable loading — instructions should be present at session start without manual steps
- Works across machines (new machine setup should produce a correct instructions file)

## Out of scope

- Changes to `~/.agents/skills/` or the skills system itself
- Project-level `AGENTS.md` files in individual repos
- Any changes to how the Copilot CLI loads instructions (external bug)

## Current state

| File | Tracked? | Content | Problem |
|------|----------|---------|---------|
| `~/.copilot/copilot-instructions.md` | ❌ No | Universal rules + system paths + file map | Mix of shareable and local; untracked |
| `~/.agents/AGENTS.md` | ✅ Yes (agents repo) | Project-agnostic behaviour rules | Loaded via env var that is itself untracked |
| `COPILOT_CUSTOM_INSTRUCTIONS_DIRS` | ❌ No | Points to `~/.agents/` | Set somewhere but not in any tracked file |

## Proposed architecture

### Layer 1: `~/.copilot/copilot-instructions.md` (primary, reliable loader)

Managed by chezmoi as a **template** (`source/dot_copilot/copilot-instructions.md.tmpl`).

- Universal content (behaviour rules, skill management) hardcoded in template → tracked
- System-specific paths resolved via chezmoi `promptStringOnce` data variables → not tracked,
  but prompted once per machine and stored in chezmoi's local config
- Template is committed to dotfiles repo; rendered output is generated by `chezmoi apply`

This is the primary loading mechanism — it's the dedicated user instructions path and
doesn't depend on environment variables.

### Layer 2: `~/.agents/AGENTS.md` (secondary, project-scoped always-on rules)

Stays as-is (tracked in agents repo). Loaded via `COPILOT_CUSTOM_INSTRUCTIONS_DIRS`.

The env var must itself be tracked and set reliably — added to the chezmoi-managed
shell environment config so it's present whenever a terminal session starts.

### System-specific data (chezmoi variables)

Paths that vary per machine become chezmoi data, prompted once via `promptStringOnce`:

| Variable | Example value |
|----------|---------------|
| `obsidianVault` | `~/Library/CloudStorage/OneDrive-.../Notes` |
| `admitCodebase` | `/Users/paul.hendrick/local/admit/main` |

These are stored in `~/.config/chezmoi/chezmoi.toml` (local, not in source), injected
into the template at apply time.
